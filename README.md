# TLP · Контроль

Сайт для вхідного й вихідного контролю знань 8 кроків процедури керівництва підрозділом (Troop Leading Procedures). Працює без сервера: сайт на Netlify, результати в Google Таблиці.

- **Вхідний контроль** (форма A) — до початку навчання. 24 питання, по 3 на кожен крок.
- **Вихідний контроль** (форма B) — після навчання. Інші 24 питання того самого рівня.
- **Журнал інструктора** — за кодом доступу. Зіставляє обидва результати кожного слухача: приріст загалом і за кроками, найслабші кроки групи, статус зарахування. Експорт у CSV.

## Де що лежить

| Шлях | Що це |
|---|---|
| `site/` | Готовий сайт. Саме цю теку публікує Netlify. |
| `site/config.js` | Налаштування: URL Google Таблиці, поріг зарахування, показ розбору помилок. |
| `site/assets/questions.js` | Банк питань: 48 питань, правильні відповіді, пояснення. |
| `apps-script/Code.gs` | Скрипт для Google Таблиці, що приймає результати. |
| `netlify.toml` | Налаштування Netlify: публікувати `site/` без збірки. |

## Публікація на Netlify

**Автоматично з GitHub (рекомендовано).** Netlify → ваш сайт `tlp-kontrol` → **Site configuration → Build & deploy → Link repository** → оберіть цей репозиторій, гілку `main`. Налаштування з `netlify.toml` підхопляться самі. Далі кожен коміт у `main` оновлює сайт за кілька секунд.

**Вручну.** Netlify → **Deploys** → перетягніть теку `site` у поле «Drag and drop».

## Google Таблиця (збір результатів з усіх пристроїв)

Без цього кроку сайт працює, але результати зберігаються лише на тому пристрої, де пройдено тест.

1. Створіть порожню Google Таблицю (`sheets.new`), назвіть її «TLP · Результати».
2. **Розширення → Apps Script.** Видаліть увесь код у редакторі й вставте вміст файлу `apps-script/Code.gs`.
3. У рядку `const INSTRUCTOR_KEY = 'ЗМІНІТЬ-МЕНЕ';` замініть `ЗМІНІТЬ-МЕНЕ` на власний код доступу до журналу. Збережіть.
4. **Розгорнути → Нове розгортання** → шестерня → **Веб-застосунок**.
   - Виконувати від імені: **Я**
   - Хто має доступ: **Усі**

   Натисніть **Розгорнути** і дозвольте доступ до таблиці.
5. Скопіюйте **URL веб-застосунку** (закінчується на `/exec`) і вставте його в `site/config.js`:
   ```js
   SCRIPT_URL: 'https://script.google.com/macros/s/.../exec',
   ```
6. Опублікуйте сайт заново (при автопублікації з GitHub достатньо коміту).

Перевірка: пройдіть тест на сайті. У таблиці з’явиться аркуш «Результати» з новим рядком. Журнал на сайті відкривається за кодом із кроку 3.

Якщо змінюєте код скрипту: **Розгорнути → Керувати розгортаннями → олівець → Версія: Нова версія → Розгорнути**. URL при цьому не змінюється.

## Важливо знати

- Вхідний і вихідний результати зіставляються за **прізвищем і групою**. Слухачі мають вводити їх однаково обидва рази.
- Правильні відповіді містяться в коді сторінки. Для навчального контролю цього достатньо, але підготовлений користувач може їх знайти.
- Адреса скрипту видна в коді сайту, тож надіслати в таблицю запис може будь-хто. Читати журнал можна лише з кодом доступу.
- Якщо зв’язку немає, результат зберігається на пристрої й надсилається автоматично, щойно зв’язок з’явиться.
- Записи «Цей пристрій» у журналі бачить кожен, хто відкриє журнал на цьому пристрої.

## Зміна питань

Питання — у `site/assets/questions.js`. Кожне має поля `q` (текст), `options` (варіанти), `correct` (номер правильного, починаючи з 0) і `why` (пояснення). Порядок варіантів під час тесту перемішується. Не змінюйте `id` питань після початку курсу: за ними рахується статистика.

Джерела питань: ATP 3-21.8, ATP 3-21.10, FM 6-0.
